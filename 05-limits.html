第一课

Scaling Law:"大"本身就是配方

scaling laws

从第一册的玩具模型到 GPT-4,公式一行没换。变的只有三个数:参数量、数据量、算力。而 2020 年的发现是:罚分随这三个数的增长,呈教科书般平滑的直线下降(在对数坐标下)——这条经验规律叫 scaling law。

动手玩

把模型从一百万参数拉到一万亿,看罚分曲线

10⁶
参数量 ≈ 100 万
平均罚分(示意)≈ —
—

纵轴罚分是第一册第二课的交叉熵;曲线为示意(真实论文里是用几百次训练实测拟合的)。里程碑与"解锁能力"也是示意——用于感受量级,非精确对应。

规 律

一条经验幂律,和它的两个震撼推论

L≈aNα
把鼠标移到公式的某一项上试试 →
推论一:可预测——训练 GPT-4 之前,OpenAI 用千分之一算力的小模型就预测出了它的最终罚分,烧几亿美元前先看到了答案。推论二:不可预测——罚分平滑下降,但某些具体能力(多步推理、按示例学习)会在某个规模附近突然"冒出来",小模型上完全测不到,这被称为"涌现"(是否只是测量方式造成的错觉,学界仍在争论)。注意:scaling law 是经验规律,像摩尔定律,不是数学定理——没人保证它永远延续。
回到大模型
这就是为什么过去几年 AI 的主旋律是"更大":不需要新想法,只要更多 GPU,能力就按幂律兑现——这是工程史上罕见的确定性。也是为什么算力成了战略资源。近年的补充发现(Chinchilla,2022):参数和数据要配比着长,光堆参数不喂够数据是浪费——于是"数据快不够用了"也成了真问题。

alpha, a = 0.076, 12.0                         # 示意参数(量级参考真实论文)

print(f"{'参数量':>10}   {'罚分 L':>7}   {'每翻10倍降幅'}")
prev = None
for e in range(6, 13):                         # 10^6 → 10^12
    N = 10 ** e
    L = a / N ** alpha

    print(f"10^{e:<2}       {L:7.3f}     {drop}")
    prev = L

# "稳定"是它可怕的地方:想再降一格?再买 10 倍 GPU 就行。

第二课
幻觉:流畅,是它唯一被训练的美德
hallucination

  
"幻觉"不是 bug,不是偶发故障,而是这套机制的必然产物:模型被训练成"永远接出最像下文的词"——哪怕它对答案一无所知,接龙也不会停下来,而且每一步都同样自信。

李白 是 诗人 。  杜甫 是 诗人 。  曹操 是 武将 。  李白 的 朋友 是 杜甫 。

      

        
        
      

      
按一个按钮,看它逐词接龙(每个词下方是它当步的"自信度")。

      

    

  


  

    机 制
    
为什么编造和真话"手感"一模一样

    

      

        ① 训练目标是接得像,不是说得真;

        ② 接龙永不停机:不知道时,它输出的是"最像答案的东西";

        ③ 编造和真话走的是同一条流水线,语气同样自信。
      

      
把鼠标移到三条的关键词上试试 →

      
对策(缓解,非根治):让它查了再答(联网/RAG,把事实放进上下文窗口——第四册第三课);让它展示推理过程;对关键事实永远交叉核验。使用铁律:它的流畅度和可信度无关——这正是它与人最不像的地方:人编瞎话时多少会心虚,它不会。

lesson2_hallucination.py

      
import math, random
random.seed(0)

# 模型的全部"知识":四句话
corpus = ("李白 是 诗人 。 杜甫 是 诗人 。 曹操 是 武将 。 "
          "李白 的 朋友 是 杜甫 。").split()
vocab = sorted(set(corpus)); n = len(vocab)
idx = {w: i for i, w in enumerate(vocab)}
W = [[random.uniform(-0.1, 0.1) for _ in range(n)] for _ in range(n)]

def softmax(z):
    ex = [math.exp(v) for v in z]; s = sum(ex)
    return [e / s for e in ex]

for _ in range(80):                            # 第一册的训练循环,原封不动
    for prev, nxt in zip(corpus[:-1], corpus[1:]):
        p = softmax(W[idx[prev]])
        for j in range(n):
            W[idx[prev]][j] -= 0.5 * (p[j] - (1 if j == idx[nxt] else 0))

def ask(prompt):
    w, out = prompt[-1], list(prompt)
    for _ in range(5):
        p = softmax(W[idx[w]])
        w = max(vocab, key=lambda t: p[idx[t]])
        out.append(f"{w}({p[idx[w]]:.0%})")     # 括号里是每步的自信度
        if w == "。": break
    return " ".join(out)

print("见过的:  ", ask(["李白", "是"]))
print("没见过的:", ask(["曹操", "的"]))
# 「曹操 的 朋友 是 诗人」——语料里根本没有这句话。
# 它把「的→朋友」「朋友→是」「是→诗人」三段各自很像的碎片,流畅地缝在了一起。

  串联桥 · 第二课 → 第三课
  
它连语料里的原话都会"记错"——因为它根本没在存原话

  
幻觉揭示了一个更深的事实:模型里找不到任何一句训练语料。几万亿词的语料,压进几百 GB 的参数——装不下的。那它存的到底是什么?









  
第三课
模型 ≠ 数据库:它是一次巨大的有损压缩
lossy compression

  
数据库存原文,查询返回精确记录;模型把语料压缩成统计规律,回答时按概率重构一个答案。理解这一点,你就知道什么问题该问它、什么不该。


  

    动手玩
    
它存的不是句子,是比例——你亲手改改看

    

      
往玩具模型的语料里加句子,观察「天气 很 ___」的概率怎么变

无论语料里有 4 句还是 400 句,模型的"记忆"都只是这个比例。原句本身没有被存储——只有它们留下的统计痕迹。(高频重复的片段会被"背下来"逼近原文,这是压缩的极端情形,也是版权争议的来源。)

    

  


  

    对 比
    
体积对不上,就是最直接的证据

    

      

        
训练语料(文本)
~ 数十 TB

        
模型参数
~ 几百 GB

      

      
压缩比约百分之一,且不可逆——这不是 zip(能原样解压),而更像人读完一万本书后的"学识":书没背下来,但规律、风格、事实间的关联都在。回答问题 = 用这些规律现场重构一个答案。重构,所以流畅;有损,所以会错。

    

  


  

    回到大模型
    
实用分工从此清晰:问它"是什么/怎么做/帮我写"(规律与生成,压缩保留得最好);别单独指望它"某年某文第几条"(精确记录,压缩最先丢掉的东西)——精确的部分交给搜索/数据库/RAG,再让模型基于查到的内容作答(第四册第三课:把事实放进窗口)。这也是"联网搜索 + 大模型"成为标配的原因:两种存储,各干各的。

lesson3_compression.py

      
import math, random
random.seed(0)

def train_and_ask(corpus):
    vocab = sorted(set(corpus)); n = len(vocab)
    idx = {w: i for i, w in enumerate(vocab)}
    W = [[random.uniform(-.1, .1) for _ in range(n)] for _ in range(n)]
    for _ in range(120):
        for a, b in zip(corpus[:-1], corpus[1:]):
            ex = [math.exp(v) for v in W[idx[a]]]; s = sum(ex)
            for j in range(n):
                W[idx[a]][j] -= .5 * (ex[j]/s - (1 if j == idx[b] else 0))
    ex = [math.exp(v) for v in W[idx["很"]]]; s = sum(ex)
    return {w: ex[idx[w]]/s for w in ("好", "冷")}

for good, cold in [(3, 1), (1, 1), (1, 3)]:
    corpus = ("天气 很 好 。 " * good + "天气 很 冷 。 " * cold).split()
    p = train_and_ask(corpus)
    print(f"语料:{good} 句'好' + {cold} 句'冷'  →  p(好)={p['好']:.2f}  p(冷)={p['冷']:.2f}")
# 模型"记住"的只是比例——原句一个都没存。
# 数据库查询返回记录;模型回答重构答案。这是两种完全不同的东西。

大结局
五册合卷:整个故事,一段话讲完
the whole story

  

    
现在,你可以这样向任何人解释大模型:

    
文字被切成 token、变成向量、注入位置(第二册);几十层"多头 Attention 搬运 + FFN 加工"反复提炼,残差直通道让深楼不塌(第三册);末端打分、softmax 变概率,训练时用交叉熵罚分、反向传播求梯度、梯度下降微调几百亿参数,重复几百万次(第一册);再经 SFT 与 RLHF 驯化成助手,推理时带着温度和 top-p 掷骰子逐词接龙,视野限于上下文窗口(第四册);它的能力随规模按幂律兑现,它的流畅与真实无关,它不是数据库,而是一场持续重构的有损压缩(第五册)。

    
没有魔法,只有机制。而每一个机制,你都亲手拨过它的滑块。
